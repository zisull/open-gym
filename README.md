# 第一视角篮球 · FIRST TOUCH HOOPS

纯前端 3D 第一人称篮球单机小游戏：**Three.js 渲染 + cannon-es 真实物理**，
完全离线运行 —— **双击 `index.html` 即可游玩**，无需任何服务器或网络。

想要一个没有地址栏、像本地软件一样的窗口，就双击 **`启动游戏.bat`**（细节见文末「以应用窗口启动」）。

## 玩法

| 操作 | 键鼠 |
|---|---|
| 移动 | `W A S D`（左手，指数逼近、帧率无关，起速/滑行都平滑） |
| 转向 | 鼠标（右手，带阻尼平滑） |
| 拾球 / 弃球 | `E`（走近篮球拾球；球在身上则丢到**场地中央**） |
| 投篮（按住蓄力，松手出手） | 左键 |
| 拍球（+2 分） | **自动**：持球就一直拍，走位越快拍得越急，不占键 |
| 跳跃 / 跳投 | `空格`（持球或蓄力中起跳都算，空中松手＝跳投） |
| 取消蓄力 | 右键 |
| 进入电影院 | 走到 +Z 端墙右侧红门（发光门牌「电影院」） |
| 进入台球室 | 走到 +Z 端墙左侧绿门（发光门牌「台球室」） |
| 暂停 | ESC |

- **自由模式**：无限时，拍球分 + 投篮分合并计总分。**全场任意位置都能投篮**：
  按住左键原地起投（镜头自动瞄准篮筐），走入三分区则自动切入瞄准视角；
  拍球完全自动（站着慢拍、跑动快拍），纯氛围也照样计分，手不用分给键位。
  蓄力不足 0.06s 的误触左键会自动取消。按 E 弃球后球落在中圈，走过去再按 E 捡回来即可。
- **投篮限时挑战（90s）**：开局空投到随机投篮点（距篮 2.6–6.4m）、球已在手，
  点位周围 **1.5m 小圈内可自由走位**调整视角节奏。**每进一球立即随机传送**
  到新投篮点，未中则原地再来；连续 3 不中连击清零；球落地自动回手。
- **计分**：投篮得分 = 基础 20 × **距离倍率** × 连击倍数（1/1/2/3 封顶）。
  距离倍率从 3m 处 ×1.0 线性涨到 25m 处 ×3.0 封顶——球场之内最远也就 ×3，
  远投值钱但不离谱；HUD 实时显示当前站位的距离倍率。
- 篮筐按比 FIBA 标准**略放大一号**（圈半径 0.26m），空心入网更容易、更爽。

两项最高分分别持久化在 localStorage（`fpbb.record.*`），刷新不丢；
挑战结束弹窗附截图分享提示，方便和好友比拼。

## 墙面二次元贴画

球馆四面墙会自动挂载海报框，展示 `imgs/wall/` 里的图片。放图流程：

1. 把 JPG / PNG（也支持 webp/gif/bmp）图片丢进 `imgs/wall/` 目录；
2. 双击 `tools/gen_walls.bat`（或 `npm run walls`）——它把图片打包成
   base64 内嵌的 `imgs/wall/manifest.js`；
3. 刷新游戏，贴画自动均匀分布到四面墙（多张图轮转排布，按宽高等比缩放）。

> 为什么需要打包那一步：`file://` 下浏览器会把本地 `<img>` 视为污染源，
> 直接贴进 WebGL 会抛 SecurityError（实测于 Edge/Chromium）。因此图片必须
> 以 `data:` URL 内嵌，`manifest.js` 就是这一步的产物。目录为空时游戏静默
> 跳过，正常运行。示例图 `sample-anime-girl.png` 可随意删除或替换。

## 电影院（圆筒影厅 · 环墙皆是巨幕）

球馆 **+Z 端墙右侧的红门**（发光门牌「电影院 🎬」）走进去即切换到电影院场景：
影厅是一个**黑匣子**（厅形可切：圆筒 / 正多边形，见下），环墙上排着巨幕——**银幕数量 = 片源数量**，片单里有
3 部就 3 块屏、5 部就 5 块屏。**全厅只有一个银幕高度（6.8m，厅高 7.0m，几乎贴到天花板），
片多片少都绝不缩小**；每块屏尽量吃满自己那一段等分弧（最宽可到按视频比例排布的
1.6 倍），超出部分靠「等比放大后裁掉画面边缘」填满（**永不拉伸变形**），所以
4 部以上就能铺满一整圈。影厅中央是一张**圆形小床**（没有围栏和靠背，视线零遮挡），
**站到床边左键即入座**（任意位置、任意朝向），入座后按住左键拖拽自由环视、
**滚轮拉近拉远**（变焦只改视野，起身自动复原），底部弹出放映条（播放/暂停、控制台、
放大观看、隐藏、起身、退出影院）。点「**🧍 起身**」或直接 WASD 走动即可起身；
想回到球场，点放映条最右的「**🚪 退出影院**」——厅里**没有门**，一整圈墙全是幕。
放映条点「**隐藏**」就整个收起来（观影不被按钮挡），左下角留一个「**☰ 放映条**」小钮点一下唤回。
「**⛶ 放大观看**」把全部片源按各自比例铺满整屏（无黑边），并且**加片 / 删片就在这个平铺视角里做**（见下）。

### ⬡ 厅形：圆筒 ⇄ 正多边形（控制台一键切换，自动记住）

「**◯ 圆筒厅**」= 96 段柱面墙 + 弧形幕（切自柱面的补丁几何）；「**⬡ 多边形厅**」=
**几部片就是几条直墙**（3 部三角形、4 部正方形、6 部六边形），每面墙一块平面幕。
两种厅形共用同一套槽位语言：`arcW(arc)` 把圆心角换算成「弦长 / 弧长」，`wArc(w)` 是反向，
所以等高、吃满槽位、按视频比例最多加宽 1.6 倍这些规则在两种厅形里完全一致。

- **观看距离不变**：厅的大小由**内切半径**（墙到轴心的距离）定，多边形取过顶点的外接圆
  `rc = ap / cos(π/n)` 来建壳，所以切换厅形时座位到幕的距离一模一样；
- **3~5 边略微收小**（`config.js` 的 `polyK: {3:0.72, 4:0.86, 5:0.95}`）：三角形若沿用
  10.5m 内切半径，外接半径要 15.1m，墙会比幕宽一大截，收小后既紧凑又把观看距离提到 IMAX 感；
- 1~2 部片时多边形退化成三角形（多出来的边是空墙）；
- 天花板灯带、壁灯、地毯、走动范围全部跟着厅形重建（灯带在多边形厅是沿棱走的折线带）；
- 厅里**没有门**：墙是一整圈闭合的黑匣子，不漏光、整圈都能挂幕，回球场只走放映条的「🚪 退出影院」。
  走动夹取按**边法线**逐边做（不是简单 AABB），多边形厅的角落不会穿墙。

## 🎛 控制台 + ⛶ 平铺视角：各管一半

**控制台**（放映条右侧抽屉，滚动清单一行一部）管"看与听"：

| 一行里有什么 | 作用 |
| --- | --- |
| **🔊 / 🔇** | 指定这部片**是否出声**。**可以多部一起勾、同时出声**，勾上的行会亮橙色 |
| **▶ / ⏸** | 单独播/停这一部，不影响别的 |
| **✕** | 把这部从环上删掉（银幕、平铺格、存档一起少一块） |
| 底部「**＋ 添加视频**」 | **按这次选了几部决定动作**：选 1 部＝往环上**加一块**，选多部＝**整条替换**（上限 12 块屏） |
| 底部「**↺ 恢复默认**」 | 退回 `video/` 片单 |
| 顶部「**◯ 圆筒厅 / ⬡ 多边形厅**」 | 切换厅形：环墙弧幕 ⇄ 几部片几条直墙（观看距离不变，见上） |
| 顶部「**📡 共享窗口**」 | 把屏幕上任意窗口/网页标签挂成一块新幕（直播、比赛页都行，见下） |
| 底部「**⏳ 播放过**」 | 历史片单快照，见下 |
| 顶部「**总音量**」「**🔇 静音**」 | 总音量只作用在出声的那几路上；「静音」是全消音，再点还原上次选择 |

### ⛶ 放大观看 = 平铺编辑台（按比例拼满整屏，不留黑边）

放映条点「**⛶ 放大观看**」，全部片源直接铺满整个视口，**这里就是加片/删片的地方**：

| 格子上的操作 | 作用 |
| --- | --- |
| **整格点一下** | 切换这部是否出声（不出声的格子压暗，角标 🔇） |
| 右上角 **✕** | 从环上删掉这部 |
| 斜纹**空格**（点一下） | 「＋ 这个空位补一部」——只往**这个位置**塞一部，环上其它位不动 |
| 右上角「**＋ 加一部**」 | 单部添加到环尾（选多部请到控制台的「＋ 添加视频」） |

**拼法**（`layoutBigGrid`）：先按目标行高贪心分行，每行**按各片真实宽高比加权**把视口宽度
分完（自然行高 = 视口宽 ÷ 该行 ar 之和），再把所有行高**等比归一到视口高度**——
所以拼不满时余量是**纵向摊开**的，横向永远严丝合缝；画面一律 `object-fit: cover`，
**只裁边缘、绝不出黑边**。竖版片自然分到窄格、横版分到宽格（实测 1440×900 视口：
1 部铺满整屏；2 部各 707×760；4 部含一部竖版 → 193×229 / 610×229 / 610×229 + 1414×531）。
窗口尺寸变化、以及元数据刚到（真实宽高比确定）时都会自动重排。

不想开控制台时，**直接点影厅里的银幕**就是切换那部的出声。

### ⏳ 播放过：点「▶ 播放」即记下这一场

每次按「**▶ 播放**」都会把**当次片单（按环上顺序，含空缺位）+ 哪几路出声**存成一份快照
（`bb.cinema.playlists`，最多留最近 6 场，新的排最前，重复片单自动挪到最前而不产生副本）。
控制台底部因此出现「⏳ 播放过： ● 09-25 13:16 · 3部」这样的时间戳芯片，
点一下就把环上片单**整条换回那一场**并按当时的出声设置播放——
只有一份历史时芯片行不显示，不打扰。
快照按**文件名**匹配：`video/` 里打包过的片源重开必然对得上；临时 `blob:` 文件重开拿不到
句柄，对应位置会留成占位银幕（状态条会说明几部是本地文件），换回其它片单随时可行。

银幕顺序、各片宽高比、音量、**哪几路出声**与**厅形**（`bb.cinema.shape`）都会存进 `localStorage`，下次打开
`index.html` 自动复原成上次的排布（临时选的本地大文件重开拿不到句柄，那个位置会
留成显示说明文字的占位银幕，环的排布不变）。

片源三种途径：

1. **打包片源**：把 mp4/m4v/webm/ogg 视频丢进 `video/`，双击
   `tools/gen_videos.bat`（或 `npm run videos`）生成 `video/manifest.js`
   （base64 内嵌，单个 ≤25MB、总量 ≤40MB，超了会拖慢开机所以自动跳过），
   刷新后进影院自动排在片单里；
2. **临时片源**：控制台的「**＋ 添加视频**」（选 1 部＝加一块、选多部＝整条替换），或平铺视角里
   的「**＋ 加一部**」/空格（只能单选），直接选本地文件（任意大小，走
   `blob:` URL 流式读取，不落盘不打包）。这类文件浏览器不给句柄，重开页面
   后名字在 `video/` 片单里对不上就复原不了——想让它常驻，把文件放进
   `video/` 再跑一次 `gen_videos.bat` 即可（排布会按文件名自动归位）；
3. **📡 共享窗口**：控制台顶部点「📡 共享窗口」，在浏览器弹出的系统选择框里选一个
   窗口/标签页/整块屏幕，它就成了环上的一块幕（详见下节）。

### 📡 共享窗口：为什么不是"把网页嵌进来"

想让银幕直接播 B 站直播间这类外部页面，在 `file://` 离线运行下没有第二条路：

- `<iframe>` 被目标的 `X-Frame-Options` / CSP `frame-ancestors` 拒绝，而且 iframe 里的画面
  本来也无法变成 WebGL 贴图；
- 抓视频直链会被 `null` origin 的 CORS 挡掉，且跨域 `<video>` 必然污染 WebGL 贴图（SecurityError，
  和本地文件同一条限制）；
- 第三方嵌入地址带签名、会过期，离线小游戏不该去维护这种对接。

**`getDisplayMedia` 是唯一合法且不需要服务器的路**：用户亲手授权"共享这个窗口"后拿到
`MediaStream`，它不跨域、不 taint，直接 `video.srcObject = stream` 就接进了现有的
`VideoTexture` 流水线——画面走同一条 cover 裁剪、声音走同一套多路出声（挂上即默认出声，
控制台可关）。三条注意：

| 行为 | 说明 |
| --- | --- |
| 需要一次真实点击 | 浏览器只允许用户手势触发选择框，脚本无法代劳（无头验证也只测接线） |
| 采不采得到声音 | 选择框里勾上「共享系统音频」才有声；状态条会明确说这块幕有没有声音 |
| 一次性、不存档 | 点浏览器工具栏「停止共享」→ 视频轨道 `ended` → 这块幕自动撤下；`saveLayout` 会跳过共享源，重开页面不残留空位 |

> 同样因为 `file://` 污染限制，`video/` 里的文件不能按相对路径直接给
> WebGL 银幕贴图解码（实测 taint），所以才有 `gen_videos.bat` 这一步；
> `blob:`（文件选择器）与 `data:` 都是同源安全源。mkv/avi 等容器取决于
> 浏览器解码能力，放不进去时可先用 ffmpeg 转成 mp4。影院内计时/物理暂停，
> 挑战中途去看电影不会浪费秒数。

## 🎱 台球室（黑匣子球房 · 虚线导向就是瞄准器）

球馆 +Z 端墙**左侧绿门**进去（与电影院红门左右对称）。玩法语言与影院一致：
走过去 → 左键上手 → 鼠标转导向线 → 按住左键蓄力、松手出杆 → 右键收杆回走动，
出口只有球室条那颗 **🚪 退出球室**（重摆 = `E` 或 🀫 按钮）。

| 操作 | 键鼠 |
|---|---|
| 上手 / 出杆 | 左键（按住蓄力，力度条在球室条上；轻点＝收力不出杆） |
| 转导向线 | 鼠标横向移动（`sens` 只转瞄准线，不动人） |
| 杆法（旋球） | 球室条那颗小白球：拖红点＝定杆/高杆/低杆/加塞（详见下文「🎯 杆法」） |
| 用鼠标点球室条 | `Tab` 开/关「操作台」——上手时指针是锁的，不解锁 DOM 一律点不动 |
| 杆法（不用鼠标） | `↑↓←→` 微调红点，`0` 回中杆 |
| 收杆回走动 | 右键 或 `WASD` |
| 重摆 / 开新局 | `E` 或 🀫 重摆（对战中＝重摆并重新开球） |
| 切玩法 | 🧘 自由练台 ⇄ 🤖 对战·轻松/标准/职业（一颗按钮循环，选择记在 `bb.pool.duel`） |
| 退出球室 | 🚪 退出球室（唯一出口；走动时按 `Tab` 才点得到） |

- **计分（自由练台）**：进袋每颗 +20，清台再 +100，母球落袋（洗袋）罚 30 并自动摆回开球区；
  最高分记在 localStorage `bb.pool.best`。

### 🎱 8 球对战：规则机 + 入库记录

点 **🧘 自由练台** 那颗按钮就开局（难度即"电脑手抖多少"，见 `config.pool.duel.levels`）。
规则按休闲球房的做法收敛成 5 条，一条一个判定：

1. **开球**：谁进谁继续；开球进的球**不定组**，台面仍是开放的（第一颗落袋球才定组）；
   开球把黑八撞进袋 → 不判生死，摆回摆球点继续出杆。
2. **定组**：开放台面上第一次合法进球，按那颗球的组别定「你=全色 / 电脑=花色」，之后各打各的。
3. **犯规**：洗袋、空杆、先碰对手的球 —— 记一次犯规并**换手**（母球自动摆回，不摆自由球）。
4. **继续出杆**：没犯规且这杆打进了自己该打的球；只进对手的球或一颗没进 → 换手。
5. **黑八定生死**：本组 7 颗清完后打进黑八＝胜；没清完就进黑八、或打黑八时犯规＝判负。

**入库记录**挂在屏幕正上方（`#pb-book`）：每行一方，彩片按落袋顺序排，
花色球画成白底彩带、全色实心，本组清空后那行的标签自动变成 **打黑八**，
犯规次数与 `3/7` 进度跟在行尾；开局方行首有 `▶`。整局判定与胜负文案也写在这一条上。

> 为什么它在顶部而不是球室条里：`#pool-bar` 用 `transform: translateX(-50%)` 居中，
> 那层会把子元素的 `position:fixed` 一起锁死，且 15 颗彩片会把三颗按钮挤出屏幕右缘。
- **相机**：`aimT` 一个权重同时混合位置与朝向，第一人称 ⇄ 杆后视角双向平滑；
  出杆后视角定住跟着球跑，收杆再交还第一人称。

### 导向线为什么敢信：物理与预测是同一套算式

台球不用 cannon-es，台面是**手写的 2D 物理**（`src/pool.js`）：如果预测走一套
数学、积分器走另一套，虚线就会"撒谎"。现在两者共用同一份数据与同一段代码：

| 机制 | 做法 |
|---|---|
| 库边＝带袋口缺口的线段 | `RAILS` 一份数组同时驱动**反弹判定**和**库边建模**，几何与物理不可能对不上；缺口内不拦，越过库线即进袋 |
| 滚阻 | `a = 0.95 + 0.35v`：慢球被常数项干脆刹住，6.6m/s 的开球约 3.4s 停台 |
| 子步 | 自适应加密（`maxSp·h > R·0.7` 就加倍，上限 64），杜绝穿球穿库 |
| 幽灵球 | 目标球按 **2R 半径**做射线求交，交点就是母球球心该到的位置——画出来的圆即接触位置 |
| 三种判法 | 线上有球→幽灵球+目标球方向+母球分离切线；没球→撞库镜像反射；对着袋口→进袋线 |
| 不闪 | 台面（含袋口、开球线、库边投影）全部画进**一张贴图**，虚线整体抬离呢绒 8mm 且 `depthWrite:false`，无球影、无共面面片 |

**回归实测**（`index.html?mode=free&loc=pool&demo=pool`，无头 Edge + 手工步进）：

```
AIM   主线=2/1.21 目标线=0.46 正中=Line:1.70@0.51,0.83,0   ← 屏幕正中就压在这条虚线上
TURN  kind=rail 主线=2/0.69 反射线=0.52                    ← 线上没球时自动换成撞库算法
SHOT  ghostErr=0.0001 dir·pred=1.000 cue停=[0.066,0.011]    ← 实际接触点离预测幽灵球心 0.1mm
POT   live=15 potted=1 score=20                            ← 直线入袋真的进袋并计分
POTCUE fouls=1 cue=-0.695,0 sunk=0                         ← 洗袋判罚 + 静止后自动摆回
```

**规则机回归**（`&demo=rules`）：跳过物理，用 `debugRuleShot(进球号, {first, cue})`
把"这一杆的结果"直接喂给判定，于是每条规则都是确定的断言：

```
A 开局 ph=break | B 开球进4 → ph=open grp=-- turn=0（不定组、继续出杆）
C 开放台进3 → grp=ST（你=全色）chips=2 | D 先碰花色 → foul=1/0 turn=1
E 电脑出杆 strokes=0→1 mode=roll       | F 整桌停稳 turn=0（电脑没进 → 交还）
H 未清台进8 → 电脑胜 · 本组还没清完就进了黑八
I 清台后黑八 → 你胜 · 清台后一杆黑八（入库条出现「打黑八」标签）
J 进球同时洗袋 → 换手 + 母球摆回 | K 空杆 → 换手 | M 开球撞进黑八 → 摆回、turn=0、live=16
```

> 这条断言链抓出过两个静默 bug：主导向线读错字段（`g.x` 而非 `g.gx`）导致顶点
> 全是 NaN、整条线不渲染且不报错；台身盒顶面高过呢绒，把整块台面盖成木头。
> 规则机自己抓到一个更隐蔽的：**先改 `phase` 再判定组**，结果开球进的那颗球顺手定了组。

### 🎯 杆法：小白球上的红点拖到哪，就打哪

主流台球游戏都把杆法做成"一颗白球 + 一个可拖的击球点"，这里照抄这个心智模型：
球室条上那颗小白球就是母球，红点＝皮头撞上去的位置。

| 红点 | 杆法 | 现象 |
|---|---|---|
| 正中心 | 中杆 | **定杆**：速度全交给目标球，母球几乎停在接触点 |
| 下方 | 低杆（拉杆） | 撞完目标球，母球沿原出杆线**自己退回来** |
| 上方 | 高杆（跟进） | 母球跟着目标球继续往前压 |
| 左/右 | 加塞 | 平时看不出来，**吃库那一刻**兑现：出射角整边偏过去 |

只有两条公式，而且**导向线与积分器共用同一份**（`cueAfterHit` / `railBounce`），
所以虚线画出的分离方向就是待会儿真走的方向：

- 高低杆 `sy` 在本杆**第一次吃到目标球**的瞬间兑现、用掉即清：`v' = v − n·j + (v/|v|)·(sy·follow·|v|)`；
- 加塞 `sw` 在**每次撞库**时沿库边推一把，随后翻边衰减（`sw *= −0.55`）；两者都随滚阻按 `decay` 消耗。

上手时指针是锁的、DOM 点不动，所以给了两条路：**`Tab` 开「操作台」**（解锁 + 球室条亮起，
红点随便拖、条上按钮随便点，再按 `Tab` 或点一下球台回到瞄准），以及**方向键 `↑↓←→` 微调 / `0` 回中杆**。
杆法 300ms 防抖写进 `bb.pool.spin`，下次进馆自动恢复。

**回归实测**（`index.html?mode=free&loc=pool&demo=spin`）：

```
STUN  中杆：接触后母球速度=0.079 位移=0.003              ← 定杆停在接触点
FOLLOW 高杆：位移=0.852  预测分离=1.000,0.000 实际={x:1,z:0}
DRAW  低杆：位移=-1.15  预测分离=-1.000,0.000 实际={x:-1,z:0}  ← 白球真的自己回来了
GUIDE 预测==实际 高杆 dot=1.000 低杆 dot=1.000
CUSH  出射角 无塞=-1.003 左塞=-0.831 右塞=-1.221（左右差 0.390rad）
CUSH  预测==实际 左=0.998 中=1.000 右=0.996
HUD   开台=1 → 拖后=低杆左塞 → 关台=0                    ← Tab 那条路
SAVE  落盘=0.600,-0.350 名称=低杆右塞
```

> 截图：`&demo=poolaim&spin=0.55,-0.85`（瞄准态的红点+分离线）、再加 `&hud=1` 看开台后的操作台。

### 🤖 电脑对手：没有身体，只演"它怎么瞄"

陪练机器人不需要模型：轮到它时，球室自动上手，**用同一套虚线导向**把瞄准过程
演一遍（想一下 → 导向线扫向目标 → 力度条爬满 → 出杆），玩家全程是第一人称视角在看。
三档难度就是准星抖动与力度抖动（`config.pool.duel.levels`）。

剩下的难点不在"能不能进袋"，而在**做球**：

1. **叫球/走位**：打完这颗要把母球停到下一颗的有利位置，等于每次出杆前再做一次
   整桌搜索 + 力度反解（分离线方向 × 距离 → 所需速度），是规划而非模拟；
2. ~~规则状态机~~ —— 本轮已落地（见上一节），所以现在才有"你来我往"的骨架；
3. **防守与斯诺克**：要评估"对手视角下哪些线被挡"，搜索空间再翻一倍。

## 以应用窗口启动（可选）

双击根目录的 **`启动游戏.bat`**：它按「Edge(x86) → Edge → Chrome(用户目录) → Chrome(程序目录)」
找到浏览器，用 `--app=file:///.../index.html` 开一个**没有地址栏、没有标签页**的独立窗口
（1600×900，可在桌面随意拉伸），看起来就像一个本地小游戏客户端。

- 浏览器配置与游戏存档（最高分、影院排布、放映片单）都写在同目录的 **`.playdata/`** 里，
  不污染你平时上网用的 Edge/Chrome；删掉 `.playdata/` 就等于恢复出厂。
- 因为用的是独立 profile，**这份存档和「直接双击 `index.html`」那份是两套**，
  挑一种方式玩就行；想迁移就把 `.playdata/Default/Local Storage` 整个拷过去。
- 找不到 Edge/Chrome 时自动退回系统默认浏览器，功能完全一样，只是窗口带地址栏。
- 关窗口即退出，没有任何后台驻留。已把 `.playdata/` 加进 `.gitignore`。

## 性能选项

主菜单/暂停面板均有 **软阴影开关**，低配电脑关闭后仅损失阴影，帧率明显提升。
Bloom 泛光固定开启（强度低），进球瞬间自动增强。

**自适应画质**：游玩中连续 3 秒低于 40fps 会自动降低一档渲染分辨率
（min(dpr,1.75) → min(dpr,1.25) → 1.0），只降不升，避免来回抖动；不改任何玩法参数。

**HUD/提示全部脏检查**：数值不变不写 DOM；历史最高分缓存在内存，
不再逐帧读 localStorage；影院换片/删片会释放旧本地片源的 blob URL 防内存泄漏。

**DOM 命名空间**：篮球的节点一律 `power-*`（`power-bar/power-fill/power-sweet`），
台球自己的节点一律 `pool-*`（`pool-bar/pool-fill/pool-book/…`），影院是 `cb-*`/`cc-*`。
以前两处都叫 `pb-fill`，`#id` 规则互相覆盖，导致篮球蓄力条"看着消失"、
台球力度条同时也不动——同名 id 是这类幽灵 bug 的温床，新增 UI 请带场景前缀。

地板闪烁已**结构性根治**（此前调偏置无效）：真正原因是球馆壳体盒子的底面
与地板平面完全共面（都在 y=0），逐像素深度比较来回翻转产生 z-fighting。
修复方式：壳体改用逐面材质数组并把底面设为 `visible:false` 挖除，同时把
内场木地板与外围胶皮合并为**单张整馆贴图 + 单个平面**，杜绝一切共面/缝隙来源。
座椅等密集小物件不再投影，灯源投影相机收紧到场地范围，画面稳定不拉丝。
